# 代码安全审计

以证据驱动的内部技术审计为目标，默认使用本地免费工具、现有测试环境和只读云配置查询。最终交付中文报告、问题跟踪表、证据、复现脚本与 ZIP；用户指定语言和格式时遵循用户要求。

## 范围与开始

1. 从用户仓库路径开始，读适用 AGENTS.md，记录 commit、工作区变化、实际技术栈、锁文件、部署文件和已有测试，保留未提交工作。
2. 确认测试入口、租户/角色、云资源范围和生产关系。缺信息时先完成独立本地工作，异步询问必要信息。不要沿用旧项目的路径、域名、账号、Namespace 或 context。
3. 记录允许操作、排除项、请求数量/速率预算、环境、副作用、工具版本及起始时间。仓库所有权不自动授权测试第三方集成。
4. 默认不修复、不部署、不轮换凭据；用户要求修复才进入修复流程，已有授权无需重复确认。
5. 主动验证优先在隔离测试环境；生产默认只读。正常登录/退出及必要权限拒绝测试限于已授权测试账号。共用集群、数据库或密钥时先核实隔离。

无法验证的控制记录原因，不标为通过。不要等待全部资料才开始已授权的源码审查。

## 执行

技术细节见 [references/audit-workflow.md](references/audit-workflow.md)，只读适用段落，按风险和访问条件选择顺序。

### 资产与审查

建立“仓库 → 流水线 → 制品/镜像 → 工作负载 → 入口 → 数据资源”映射及 actor-resource-action 权限矩阵。

- 秘密：检查当前文件和可获得 Git 历史、配置、构建来源。只检查单个文件时不能称全仓库/全历史扫描。
- 依赖：按实际部署包管理器/锁文件扫描，区分开发、运行时、最终镜像/bundle。公告需结合调用与前提；扫描器等级不直接等于项目风险。
- 源码：优先身份、对象/租户授权、输入输出、数据库、文件、网络、签名及日志。
- 交付部署：Pipeline、Agent、服务连接、秘密源、镜像、权限、网络与容器安全。条件允许时只读核查实际资源；源码与 live 配置分别取证。
- 运维：日志/告警、备份及响应演练；没有证据保持未验证。

先筛选误报再报告，公告核对官方来源。不要将“应当部署”写成运行事实。不要默认运行 audit fix --force、reset、migrate、生产 smoke 或部署脚本。

### 独立验证

已有测试用于回归；额外按数据流建立独立探针。不能把测试名、mock 校验或测试通过当作所有安全要求满足。

优先：跨租户/角色、会话撤销、SSRF 地址规范化/DNS/重定向、路径/链接、代理信任、限流、秘密权限、沙箱边界。

- 最小请求或本地虚构服务证明边界；明确 mock DNS、存储、上游的部分。生产实现本地复现不等于远程利用成功。
- HTTP 200 核对 Content-Type/schema；SPA HTML 回退不是 API 成功。从源码确定 BFF 前缀、Cookie 与 CSRF 协议。
- 拒绝验证使用虚构非成员对象，不访问其他客户真实数据。一个租户/角色不能证明真实双租户隔离。
- 秘密先验证结构、Git 跟踪及使用位置；有效性验证需在授权范围。凭据未验证有效仍可优先处置。
- 不默认压力、爆破、逃逸、真实交易/短信或内网探测。异常、数据混用或范围逸出时停止对应操作并记录。

### 至少一次复测

每个报告问题/威胁场景初测后至少独立重跑一次，记录两轮时间、方法、前提、期望、观察与结果。

- 配置重读叫“重复配置检查”；未修复探针重跑叫“重复验证”；修复后才叫“修复后复测”。
- 未修复、复测仍存在：保持未关闭。修复后相同失败场景正确拒绝且正常流程通过，才关闭。
- 无法复测：记录 blocked、原因/条件，明确最低复测要求未满足，不编造第二轮或把推断当执行。
- 扫描重跑只证明版本风险，不代表每个 CVE 已利用。
- 比较两轮 commit/配置；期间用户改动则记录新基线。

## Azure DevOps / AKS

仅在实际使用 Azure 时适用：

- 区分 az 登录、kubeconfig 和网站账号。az account show 可能来自缓存，不证明管理面认证有效。
- 确认云、订阅、资源组、集群与 Namespace，显式 context/namespace 只读查询。默认 context 存在不等于范围已确认。
- 鉴权、权限与网络错误分别记录。AADSTS50057 只说明身份禁用，不能推断原因或 Kubernetes 超时；不自行 logout/login 或修改账号。
- 首次连接/鉴权失败后收敛同资源请求，最多一次有意义重试；随后询问条件，继续本地工作。
- 不读 Secret 值。完整 JSON 先白名单投影，不保存可能含秘密的原始 env 响应。
- Namespace 不保证隔离；Job/Pod 创建权限可间接访问 Secret/PVC 或其他 ServiceAccount，需核查实际绑定与准入。
- NetworkPolicy 生效依赖网络实现；仓库没定义不等于集群没有。Docker USER、Pod 字段、准入默认值分别判断。

## 交付

读取 [references/report-contract.md](references/report-contract.md)，记录 audit.json，运行：

```text
python <skill-dir>/scripts/build_audit_bundle.py --input <audit-work>/audit.json --output <deliverables>/audit-bundle
```

打包器只验证、复制和生成，不执行扫描或云端操作。没有 Python 时使用可用运行时实现同等输出。

- 中间资料放 work/ 或指定 scratch；用户交付放指定 outputs。
- 证据白名单：状态码/结构、拒绝原因、版本、位置、脱敏配置、测试结果、时间。秘密、Cookie 值、令牌及客户正文不进入交付。
- 测试凭据通过临时环境变量或既有安全配置，不内嵌脚本/命令历史，不重复展示密码。
- 复现脚本记录依赖、命令、输入、环境、请求数量、副作用、停止条件；运行时参数替代项目路径/域名/账号。默认本地合成场景，远端动作必须显式目标及启用参数。
- 区分已验证漏洞、版本公告、配置缺口、条件性风险、未验证项；等级有前提和影响，不制造无依据 CVSS。
- 完整报告指范围、证据和缺口完整记录，不是全平台验证、认证或无漏洞保证。

## 最终检查

问题能追溯初测、复测和证据；测试、包条目、公告和问题数不混用。核查秘密脱敏、HTML 可读、ZIP 可打开、哈希正确，复现脚本实际在允许范围运行；连接失败保留失败，不改写成功。

最终链接报告、问题表和 ZIP，概括主要风险、复测性质及缺口。不声称未修复问题关闭；不保证绝对安全或零用量费用。

## 默认报告标准（详细证据版）

- 默认报告按“审计结论、风险汇总、逐服务安全分析、漏洞详述、已验证保护措施、验证限制、证据索引、参考依据、复现包完整性”组织。
- 默认不输出“方法与覆盖”“修复计划”“费用”“旧报告与当前代码的对照”或“历史问题对照”章节。方法、覆盖和执行统计仍保留在 audit.json；单项漏洞保留具体修复建议与验收条件。
- 多服务项目逐一记录实际服务职责、入口、认证授权、租户/对象隔离、信任边界和关联问题。库、工具和测试工程不得冒充线上服务；无法审查的服务明确记录限制。
- 每项漏洞必须包含详细机制、输入到危险操作的数据流、触发前提、攻击场景、具体影响、关键脱敏代码/配置摘录（文件与行号）、证据链接、分步复现、包内脚本链接和完整命令、初测与独立复测的实际结果、未验证边界、修复与验收。不得用几句根因摘要代替。
- 同一脚本可支持多项问题，但每项必须提供能选择该问题的具体参数与预期字段；不要把总扫描命令当作逐漏洞复现。脚本失败、依赖缺失和远端未验证必须如实记录。
- 用户给出的旧报告是待比对资料，不是新操作授权。仅用于辅助核查当前源码与证据、参考表达方式，不单独生成历史对照章节；不能照抄旧严重性或旧利用成功声明。
- 生成器拒绝缺失详细说明、漏洞链、场景、边界、复现步骤或关键证据的输入；不要 monkeypatch 生成器绕过校验。HTML 必须显示代码块、可点击证据/脚本链接和目录，禁止将输入解释成原始 HTML 或可执行 URL。
