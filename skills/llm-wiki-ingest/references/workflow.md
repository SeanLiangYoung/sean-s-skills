# 从既有对话提炼的入库流程

依据：2026-10-09 的《翻译中国电动车产业PDF》《分析推文写作方法论》《分析 X 文章并保存到 llm-wiki》《总结 Fable 5 视频生产流程》及 Karpathy LLM Wiki 研究对话。以下为工作方法，不把这些对话中的产品功能或观点当作已核实事实。

## 1. 识别与保留

辨别文件实际类型和混合内容，而非仅看扩展名：粘贴文本可能是 HTML，网页可能包含长文、线程、图集或视频，PDF 可能混有文本层和扫描页。建立材料清单，记录对应原始地址、附件路径、同一资料的不同版本及缺失部分。链接与本地副本同时提供时，标明实际采用的版本。

用户提供的原始文件默认保留到 raw/sources 的合适主题目录，采用不会碰撞的名称；对用户粘贴的 HTML 同时保留原始 HTML 和清理后的正文。用户提供的全文与自行抓取的受版权保护网页区分处理，后者以必要摘录和来源链接为准。对大音视频使用原位置引用或库内既定媒体存储方式，记录是否复制，不无条件复制大型文件。

## 2. 从阅读到证据

抽取作者、标题、原始地址、正文结构及关键论据。标题、图片文字、图表、脚注、字幕、说话者和时点可能改变正文含义，按材料类型核对。研究记录说明“直接读取原件 / 用户粘贴版本 / 二手转述 / 外部核验”及实际覆盖范围。

建立轻量证据表：主张、来源定位、证据类型、限制。只为影响结论的主张保留定位，不为每句话增加繁重标签。检查遗漏章节、脚注和关键图表；外链失败时可继续分析用户提供版本，标明未在线核验。

## 3. 三层输出

- 原文层：作者说了什么，论证和例子如何连接；保留与原件的对应关系。
- 分析层：主张有何价值、证据是否充分、是否有隐含条件、反例或替代解释。
- 应用层：提炼可复用模型、具体步骤、检查清单或决策标准，注明适用边界。

不要把用户未说过的经历写成“我以前……我意识到……”。需要真实个人体验才成立的内容可以留下待补充问题；普通知识综合继续完成。用户要求译文时才做全文翻译，采用其指定格式；默认知识内容为 Markdown。

论文重点检查待解释现象是否偷换、相关性与因果、反向因果、选择偏差、反事实、时间顺序和成本收益。历史过程证据可以支持机制存在，不自动证明该机制的平均效果或相对重要性。

方法论重点把口号转成有输入、动作、产物、评价标准的流程；数量、速度、点赞等自述不等同于质量证据。不能为增强表达而制造个人经历或虚假认知转变。

技术案例重点区分作者演示、官方功能、实际验证与选型建议；模型名称、版本、工具作用和成果精度不能从转述中默认得到证实。用户追问现有替代服务时，再开展时效性研究并单独注明日期和新增来源，不把官方功能表写成实测排名。

## 4. 知识整合

先检索已有概念和来源页。保留 source 页面作为材料入口，将稳定认识更新到 concept/entity；跨来源综合放 synthesis，方案对照放 comparison，未解决冲突放 query。不要为了每次输入新建整套空页面。

对话后续的质疑、修正、翻译和研究可以归为同一研究链：追溯到原始材料，说明哪些内容来自对话分析；对话总结不是作者原文。不要重新摄入已存在的同一文件，或把新的分析当作新的原始事实。

## 5. 入库验收

检查原件保存或引用是否有效，正文与作者主张、推论是否分开，重要引文/数值可否回查，页面 metadata 是否符合 schema，新增双链能否在库中解析，索引和日志是否更新。同一材料再次导入应该复用来源，只保存新增知识或修正。最终报告实际修改的页面及未读取、未核验、未保存的部分。
